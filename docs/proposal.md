# 大作业二方案简报

调研日期：2026-10-23。用户已批准执行；本文件保留初始规划，实施状态见README与项目报告。以下容量为规划估算，实际占用另行记录。

## 1. 要完成什么

附件第1—3页要求：3—5人组队，选择题目二时实现基于JEVDB的股票研究或交易辅助原型，展示“用户需求→工具调用→结果展示”的完整流程；说明Skills或工具的职责、输入输出、依赖、许可与权限；包含交易时说明现金、持仓、订单校验、成交价和费用。还需记录成员贡献，利用multi-agent及相关工具核验数学、文献、数据和代码，最终提交原型、源码、运行说明、项目报告和必要演示材料。附件未给出截止日期。

**建议做“面向课程小组的股票研究与组合模拟平台”。** 首版以10—20只美股、约5年日线及200—1000条有来源和发布时间的公司资料为范围；市场选择可在review时调整。只处理资料研究、组合风险和教学模拟交易，实时行情、真实券商接入和高频交易不纳入首版。

演示流程：用户输入公司筛选条件与研究日期→JEVDB语义筛选资料并关联公司→展示原文、来源和时间→计算收益率、协方差及组合权重→生成模拟订单→展示成交、现金、持仓、净值及操作记录。JEVDB必须实际参与筛选，不能仅出现在项目介绍中。

矩阵内容以中心化收益率矩阵X、协方差矩阵Σ和组合方差为主：`Σ=X^T X/(T−1)`，`σ_p^2=w^T Σw`（Word公式线性输入）。解释半正定性、特征值、病态矩阵及正则化；将只做多的最小方差组合与等权组合比较。PCA作为扩展，先保证核心流程完整。

## 2. 软件怎么选

**关键差异：附件称JEVDB基于Palimpzest，但当前作者仓库是DuckDB扩展。** 已核实题目论文的标题、作者和arXiv编号；论文将Palimpzest列为比较系统。建议采用作者现有发布包，在报告中交代与附件描述的差异；若老师另发指定代码版本，再据此调整。无需先把Palimpzest整套安装进来。[论文](https://arxiv.org/abs/2610.02046v1)、[作者说明](https://github.com/PDAIS/JEVDB/blob/main/README.md)。

| 软件或工具 | 用途与选择理由 | 安装安排 |
|---|---|---|
| Python3.13、venv、pip | 全项目使用Python，界面和计算共享数据结构 | 主机已有Python3.13.5；review后建独立环境 |
| JEVDB0.1.0、DuckDB1.4.3 | 文本语义筛选、公司与资料关联、研究数据存储 | 必须集成；DuckDB按JEVDB要求固定版本 |
| pandas、NumPy、SciPy | 行情整理、矩阵计算、带约束的组合优化 | review后验证兼容性并锁定版本 |
| Streamlit、Plotly | 浏览器界面、表格、净值曲线和风险图 | 首版界面；一套Python工程即可启动 |
| SQLite（Python标准库） | 模拟账户、订单与成交账本，事务更新 | 无需独立数据库服务 |
| CSV导入、yfinance（候选） | 可追溯行情输入；yfinance用于小规模研究获取 | 首先支持明确格式的CSV，在线接口再验证 |
| Git、GitHub、pytest | 多人协作、版本管理、关键行为测试 | Git与GitHub CLI已可用；测试工具后续安装 |
| 远程Jev或兼容模型API | 为JEVDB提供真实语义判断 | 需要可用凭证与调用预算；本轮未调用 |

JEVDB的包元数据要求Python≥3.10，直接依赖仅列出`duckdb==1.4.3`；已有Linux x86-64预编译wheel，通常无需自行编译。[依赖定义](https://github.com/PDAIS/JEVDB/blob/main/pyproject.toml)、[二进制安装说明](https://pypi.org/project/jevdb/)。Streamlit支持虚拟环境安装；全部依赖的共同兼容性仍需开发阶段实测。[官方安装说明](https://docs.streamlit.io/get-started/installation/command-line)。

开发阶段利用现有Context7核查接口、litverify核验引用；软件内拟定义四项工具契约：行情输入（代码与日期→行情表）、语义筛选（条件与文档→带依据的公司列表）、风险计算（收益率矩阵→风险与权重）、模拟交易（订单→成交与账本）。分别限制为数据读取、模型API调用、数值计算及本地账本写入权限。第三方Skills需先核实仓库与许可，再决定是否集成。

已核实JEVDB为MIT许可，Streamlit为Apache-2.0，pandas为BSD-3-Clause，Plotly为MIT；yfinance为Apache-2.0，但软件许可不授予行情再分发权。yfinance项目明确提示数据使用受Yahoo条款约束，因此公开仓库先放获取说明，不上传下载的行情全集。[JEVDB许可](https://github.com/PDAIS/JEVDB/blob/main/LICENSE)、[Streamlit元数据](https://pypi.org/project/streamlit/)、[pandas元数据](https://pypi.org/project/pandas/)、[Plotly元数据](https://pypi.org/project/plotly/)、[yfinance说明](https://github.com/ranaroussi/yfinance)。其余直接与传递依赖在锁定版本时补齐许可记录。

## 3. 占多少存储

主机实查：i7-11700、16逻辑CPU、约46GiB内存；工作目录所在磁盘可用约201GiB，/tmp使用约2%。这套小规模原型可采用CPU计算及远程推理，无需为首版购置GPU或下载模型权重。当前默认Python环境只有NumPy，尚未具备项目所需的完整依赖。

PyPI元数据给出的压缩下载体积：JEVDB wheel约2.14MiB；DuckDB1.4.3的Python3.13 Linux wheel约19.55MiB。下表还计入其他依赖、解压和缓存，不能用两个wheel的大小代表整个项目。[JEVDB发布文件](https://pypi.org/project/jevdb/#files)、[DuckDB发布文件](https://pypi.org/project/duckdb/1.4.3/#files)。

| 本地占用项目 | 规划估算 |
|---|---:|
| Python虚拟环境及完整依赖 | 1—2GiB |
| 安装下载缓存 | 0.3—1GiB |
| 行情及公司资料 | 0.05—0.3GiB |
| 研究数据库、交易账本与日志 | 0.1—0.5GiB |
| 源码、报告、截图及短录屏 | 0.2—1GiB |
| **合计 / 建议预留** | **约2—5GiB / 10GiB** |

估算按小规模日线研究计算：20只股票×5年×每年约252条日线，约25200行；协方差矩阵仅20×20，行情计算本身占用很小。长期日志、录屏和依赖缓存更影响容量。运行内存暂按2—4GiB预算，待实测；模型权重占用为0。若必须源码编译JEVDB或改用本地模型，应重新估算，不能沿用上表。

GitHub只保存代码、配置模板和文档，目标控制在50MiB以内；虚拟环境、原始资料、行情、密钥及录屏保留本地。API调用费用与磁盘容量分开计算，待选定供应商后制定限额并记录实际用量。GitHub仓库用于协作，原型首先在本机运行。

## 4. 开发顺序与验收重点

review后依次完成：①安装并锁定依赖，验证JEVDB真实查询与API连通；②接通可追溯的数据输入和语义筛选；③加入矩阵风险计算、优化和基准比较；④加入模拟交易、界面及演示；⑤整理分工、核验记录、项目报告与运行说明。

模拟规则建议固定为：只做多、整数股、无杠杆，研究信号在下一交易日开盘撮合，手续费及滑点为可配置的教学参数。校验金额、数量、现金与可卖持仓；现金和持仓在一个事务中更新，重复点击不得重复成交。这些是原型的简化假设，需在界面和报告中明示。

验收聚焦五件事：JEVDB确实处理真实资料并保留依据；行情的缺失、重复、时区及复权口径明确；历史研究只使用当时可获得的信息；矩阵结果与手算小例子一致且优化约束满足；订单拒绝、费用与资金持仓更新正确。语义筛选用少量人工标注样本核验，性能和费用只报告实测值。API失败时明确报错，离线回放只使用此前真实运行的已保存结果并标注来源。

3—5名成员可按数据/JEVDB、矩阵方法、模拟交易、界面及报告分工。按附件要求在开发阶段安排有明确问题的multi-agent核验，保存发现、修正及贡献记录；本次仅完成方案调研，未启动多Agent开发或生成任何实验结果。

需要在review中定下的范围：美股还是A股；是否接受上述组合风险与模拟交易主线；可用的模型API来源及预算。若改为A股，须补充相应交易规则和数据源方案。
